# Review 問題清單

## 第一題：「我想……」測試

寫出這個功能會讓玩家說出的句子。好的例子：

- 我想打贏那個現在打不過的人。
- 我想存錢買那把武器。
- 我想去那個很遠的地方看看。
- 我想把機械練高，看看那扇門後面有什麼。
- 我想跟這個人繼續旅行。
- 我想冒險私吞這批貨，看能賺多少。
- 我不想得罪這個城鎮，所以這次還是照約定交貨。

如果只寫得出下面這些，就不是俠客遊式玩法：

- 系統叫我按這個。
- 數字從 25 變 30。
- 地圖多一個節點。
- 任務名稱不同，但操作一樣。

## 逐項檢查

**慾望**
- [ ] 它讓玩家看到一個「現在做不到、但想做到」的東西嗎？
- [ ] 做不到的原因寫在畫面上嗎（鎖住並寫明需求，不是藏起來）？
- [ ] 它能接進一條既有的慾望鏈，或開出新的一條嗎？

**自由**
- [ ] 不同的選項真的導向不同的結果、成本或後續嗎？
- [ ] 不同背景／能力的角色，會先走到不同地方嗎？

**代價**
- [ ] 每個選擇都有成本嗎（時間、錢、補給、戰鬥、關係、機會）？
- [ ] 代價在選擇之前就講清楚了嗎？
- [ ] 偏離約定的後果由世界記住嗎（寫在收據裡，而不是一個旗標）？

**旅行與世界**
- [ ] 這趟路的終點有玩家想要、別處拿不到的東西嗎？
- [ ] 新地點會改變路線，並且連到城鎮的經濟、工作或危險嗎？
- [ ] 查過世界的實際數字，後果大到感覺得到嗎？

**戰鬥**
- [ ] 戰鬥有目的嗎？有合理的避戰選項嗎？
- [ ] 下一步和傷害在做決定之前就看得到嗎？

**人生**
- [ ] 錢有地方變成成長嗎？
- [ ] 它是在前一層被證明之後才加的嗎（見 companions-and-life.md 的順序）？

## 反例（看到就擋）

- **把自由誤解成選項數量**：SEARCH / SEARCH HARDER / SEARCH CAREFULLY 結果本質相同，不算自由。
- **把長期目標做成 achievement checklist**：慾望要從世界情報形成，不是 UI 指派「人生任務 1/10」。
- **用大量城鎮代替值得探索的世界**：三城加十個有意義的地點，勝過十五座功能相同的城。
- **所有成長都只是數值增加**：最有感的是「以前不能做，現在能做」。
- **戰鬥成為預設答案**：要有理由，也要有合理的避戰時機。
- **工作只有成功／失敗**：延遲、放棄、轉賣、私吞、改變立場才是人生。
- **先做人生模擬的外殼**：婚姻、孩子、老化要建立在值得在乎的世界之上。
- **後果只是一個旗標**：背叛之後世界沒有任何可感覺的變化。
- **照例子不看數據**：設計討論的例子和遊戲實際數字衝突時，以數字為準並記錄偏離。
- **嘮叨**：同一個問題每次經過都問一次。
- **技術通過＝好玩**：測試證明規則正確，只有真人試玩能證明好玩。
- **灰掉的按鈕不說原因**：做不到的時候，畫面要說為什麼、要去哪裡（「到乾井才能交貨」「回灰谷領賞」）。玩家不會去猜規則，只會以為遊戲壞了。

## 試玩時要問的問題

每個 slice 交付時，列 1–3 個只有真人試玩能回答的問題，例如：

- 看到打不過的目標時，你會不會想「先去做別的，變強再回來」？
- 有沒有哪個地點讓你改變了原本要走的路線？
- 拿到可以私吞的貨時，你有沒有真的猶豫？
- 玩了 30 分鐘後，你自己知道下一步想做什麼嗎？還是在等遊戲告訴你？

試玩的原話要記進 `PLAN.md` 的 Decision Log，它比任何測試數字都更能決定下一步。
