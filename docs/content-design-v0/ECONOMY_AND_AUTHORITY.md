# 內容如何進入世界

本批是 DESIGN_ONLY。既有 runtime 仍只有 ITEM-1 十二筆最小定義，以及先前
Field Combat Lite 的獨立示例。這裡所有新動作、報酬、估值與任務期限都沒有接線。

## 三聚落的任務性格

| 聚落 | 既有世界依據 | 本批候選需求 | 不可直接宣稱 |
| --- | --- | --- | --- |
| 新希望 | 水與糧食產出 | 耕種、井水管理、保種、補給與照護 | 任務文案能增加人口或直接加產量 |
| 灰谷 | 廢料與工業來源 | 拆解、換件、工序、污染調查、工人分歧 | 所有工業殘骸都可安全拆解 |

## 物品流通

每件物品分別描述產地、可能取得容器、三地供應、三地需求與理由。供應低不代表
需求低；需要工具的地方可能正因工具缺乏才委託運送。交貨需來源庫存、合法所有權、
運輸和目的地收貨提交，不能僅憑事件文字把十把扳手生成到商店。

rarity 是設計搜尋提示，不是掉落概率。普通物品可因具體工作而有價值。
獨特物不進例行庫存；未知奇物不設全世界通用高價。文件的私人、歷史、技術用途分開。
取得、借用、交還、消耗、隔離保管須分別記錄，不能同一物體留在兩個 owner 下。

## 任務如何回應世界

1. 發出委託時，讀取真實的庫存、已存在的NPC、商隊、路況與日期。
2. 接受時重驗；已出發的商隊不能為玩家倒退，失去資格或已死亡的委託者不能繼續出票。
3. 選擇只提出 intent。物品移轉、期限、工作成果分別由正式 owner 驗證後原子提交。
4. 結算顯示實際增減和日期，玩家確認後才繼續。未鑑定可以保留未知性；結算不能含糊。
5. 價格、人口與商隊反應由世界模擬依正式事實推導。任務不能同時手動加產量、降價、
   補人口、再生成新商隊，避免同一成果算四次。

「不介入」是世界繼續運作的條件，不是固定懲罰。期限關閉可以只是車已出發、
另一工人接單、需求已消失。遭襲、死亡與遷徙只在對應 authority 真正提交後成立。

## 尚缺的實作邊界

| 內容說法 | 最少需要補上的權限 |
| --- | --- |
| 持有、借出、交貨 | Item instance / ownership / atomic transfer |
| 穿戴、工具可用 | Equipment slot / condition / action capability |
| 水、糧、燃料進入物品 | 與既有 aggregate resource 的明確 adapter；禁止隱式 1:1 |
| 修復或拆解 | 設備狀態、材料來源、合法操作、耗時與產物的 owner |
| 食用、醫療、防護 | 對應 survival / injury / hazards；不能由 tags 執行 |
| 對話、信用、工作 | NPC identity binding / relationship / jobs / deadlines |
| 路線或產量改變 | 正式設施或路線 state；沿用世界時計，不增設平行日期 |
| 文件、奇物知識 | 已知事實、來源、版本與辨識權限 |

crafting-proposals.json 及材料關係圖刻意沒有配方數量、產率或售價。循環邊可能是
維修後再拆料的合法方向，也可能形成套利；只有未來量化所有投入、工時、耗損與
物體唯一性後，才能驗證。此處不宣稱經濟已平衡或不存在免費循環。
