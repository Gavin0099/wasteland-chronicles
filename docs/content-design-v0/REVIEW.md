# 內容設計 V0 整合審查

這批交付完成四套相互引用的設計稿，以及檢查與擴充工具。它沒有把內容註冊到遊戲。
實際計數、重產指紋和反例檢查見 [驗證紀錄](VERIFICATION.md)。

## 內容取捨

- 185 件物品分為 38 武器、34 工具、20 衣物、12 容器、28 消耗品、53 雜項。
  保留原美術名稱和十二筆正式定義的 ID／重量；鹽、電池不因跨類別而複製。
  三張分類示意圖不是實物，未知奇物及獨特物沒有強塞通用價格。
- 480 遭遇的主要方向是探索 183、生存 151、交易 131、對抗 15；共有 1,448 個選項。
  武器數量相對對抗內容偏多，所以首輪只保留基準武器與既有撬棍的橋接方向，
  不為了使用美術而擴充戰鬥。這些比例是編輯分類，不是遊玩頻率。
- 120 任務各城 40，涵蓋工作、生活、經濟、利益衝突、探索及世界狀態。
  360 條方案分別寫門檻、代價、結果；期限與玩家缺席的結果需讀取實際世界事實。
- 150 人物鉤子各城 50，包含公開需要、個人利害、可提供的幫助、限制及關係。
  十二個利益群體是內容分類，不是新實作的派系。人物要綁既有人口，不生成150人。
- 物品各有兩個情境用途，共 370 個；用途不只靠換物品名字，另寫相容性、來源、
  占用、不可逆交付或技能限制。完整材料圖另含十二個製作方向，尚無配方數量。

## 矩陣如何用於下一刀

[矩陣報告](derived/MATRIX_REPORT.md)保留完整未引用、沒有事件和沒有獎勵入口的清單。
無引用並不表示內容稿漏寫，也不意味應立即加入掉落；它表示這個候選仍沒有跨庫的
實際用途。三張分類圖本來就應留在實體玩法以外，其他孤立候選先留待相關機制成熟。

繩索、防水袋與布袋的引用較密集，原因是本批偏重搬運、探索與保管。持有、交付和
獎勵分開統計，不能從「出現很多次」直接認定它們是萬能工具；真正上線前還應比較
不用工具的代價、能否回收、對位置與安全狀態的要求。引用密度不等於數值平衡。

555 筆供需記錄都保留地區理由，沒有轉成價格倍率。工業地區也可能同時高供應、高
需求；唯一物不能因此定期補貨。材料圖只表示可能的投入／產物關係，沒有證明質量
守恆或不存在套利。日後必須補上數量、品質、時間、耗損與真正物品所有權再驗證。

## 審查範圍與發現

- [獨立內容審查](INDEPENDENT_CONTENT_REVIEW.md)：其他作者的110件物品、100荒野
  遭遇及60份新希望／灰谷任務；包含回讀修正。其自行撰寫的資料未冒充獨立審查。
- [用品與擴充工具審查](evidence/INDEPENDENT_REVIEW.md)：另外75件物品，以及擴充
  工具的真實資料包、反例、重跑和基準保護。區分首次獨立發現與同一審查者完成的修正。
- [內容抽核](CONTENT_SPOT_REVIEW.md)：另15遭遇和乾井核心3任務的語意抽核。
- 根代理整合檢查首輪範圍、原始作者稿與 JSON 重產，以及實際 repo 接線缺口。

本輪發現包括：放棄分支免費越過路障、延誤憑空宣稱商隊已走、任務和遭遇來源
矛盾、一般手冊被當個別物品紀錄、同一次工作可能重領報酬、人物完整支線悄悄
擴大首輪範圍，以及格式檢查接受非文字／錯誤陣列。具體修正與殘餘限制由上述
審查文件記錄；沒有把「所有檔案能解析」當成語意正確的證據。

任務的 encounter_refs 是編輯關聯，不全是可直接執行的步驟。一部分非核心任務
借用同題材的不同事實版本，已在 followup 區分改編來源、可選支線和共用工作；
不能把它們直接串為同一現場或共用結算。這個庫完成的是可選內容骨架，尚未把
120 任務全部對齊成 runtime scene graph。

不是每個事件都經過另一作者逐字審查；全庫有結構／引用檢查與作者自查，獨立全文
審查和抽樣的範圍如上。尚未做玩家測試、完整本地化校對、戰鬥或經濟平衡驗收。

## 第一輪內容的用途

[30／15／9／10 候選](FIRST_PLAYABLE_SLICE.md)先驗證有限物品、工具選法、期限和
一次性結算。九份工作以城內交付、設備與帳目問題為主；它們尚不足以證明長程探索
或《前途道標》式人生體驗。玩家測試應特別記錄：是否覺得工作過於文書化、是否
願意為工具回訪，以及旅行是否真正改變工作結果。若只有交付便利性而沒有冒險感，
應從現有庫挑選遺跡／失蹤者／跨城委託來替換，不先擴大清單。

選中人物只採用其在首輪工作與遭遇中的職務；未選的個人支線和關係另列延後，
不因加入十人就暗中加入額外人物或物品。首輪本身仍是實作提案。

## 擴充性已做到哪裡

同格式的新物品、任務、遭遇及人物使用獨立命名空間與版本，宣告跨包相依後可
產生獨立預覽。重複 ID、錯誤型別、未知引用、未知 schema 與越界素材引用會拒絕。
基準數量是 V0 的完整性要求，不是總量上限；新增內容不用改185筆基準或替舊 ID 編號。

尚未做 runtime 包載入器、存檔遷移、相依版本求解或熱更新。設計句子和 action tag
不會執行世界修改。新機制仍要獨立定義 owner，既有機制內的內容才可用資料組合。
做法與範例見 [擴充指南](EXTENDING.md)。
