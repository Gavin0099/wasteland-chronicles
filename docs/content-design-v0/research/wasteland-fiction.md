# 廢土小說參考：物品、遭遇與地方關係

查閱日期：2026-09-22（Asia/Taipei）。用途：支援 185 個既有美術名稱的內容設計、遭遇候選與世界關係矩陣。這是研究與原創設計推論，不是新增 runtime ItemDefinition、掉落表、價格公式或物品效果的授權。

以下「已查證」只描述作者或出版社公開介紹可支持的內容；「設計推論」是本專案提出的轉譯，並非聲稱小說具有對應的遊戲規則。沒有取用小說正文、譯文段落、角色台詞、地名或特殊物品名稱作為本遊戲內容。

## FICTION-ROADSIDE：回收物需要去處，未知物需要可觀察的證據

**已查證：** 出版社介紹主角冒險非法進入危險區域，帶回神祕的外來物件；這些物件已形成黑市，回收工作持續影響他的生活。[出版社書訊](https://www.chicagoreviewpress.com/media-request-pages-479.php?isbn=9781613743416)

**設計推論：** 一件奇物的內容不能停在「用途不明，售價很高」。先寫它如何被發現、玩家現在能觀察什麼、誰願意研究或收購、將它交出去會放棄什麼可能。這四件事可以形成探索動機，而不用先給永久能力加成。

**原創候選：** 「鳴石」出現在廢棄變電站附近。玩家只能確認它靠近通電設備時出聲；灰谷維修者想測試它，商隊收購者願意直接帶走。交付、保留、繼續測試各自有清楚的物品移轉與時間結果；聲音的原因仍可未知。這不代表維修者一定給高價，也不預先保證物件安全。

**內容審核問題：** 奇物是否有至少一項可驗證現象及一位有具體目的的利害關係人？移除「稀有」兩字後，玩家是否仍有理由帶它上路？鑑定、研究、污染與買家估價尚需各自 authority，不由描述文字直接執行。

## FICTION-ROAD：普通補給也能承載艱難的選擇

**已查證：** 官方指南描述父子在災後旅途中尋找食物與庇護，防範暴力威脅；指南亦討論孩子希望父親對陌生人保有慈悲的情境。[官方讀者指南](https://www.penguinrandomhouse.com/books/110490/the-road-by-cormac-mccarthy/readers-guide)

**設計推論：** 補給的意義來自「這次帶給誰、會少掉哪部分安全餘裕」，不必靠每種食物附加不同增益。援助選項需要真實成本及可理解的情境，不能每次捐贈都立即掉出更值錢的獎品。

**原創候選：** 長途出發前遇到缺糧旅人。乾糧可留作自己下一段路的補給，也可分出部分；若缺少受援者後續狀態的正式規則，就只明確記錄本次交付，不宣稱玩家已拯救整個家庭。便宜的睡袋、繩索、普通衣物可以因一次具體旅程而重要，無需改成高稀有度。

**內容審核問題：** 選擇前能否知道可見成本？結算後能否知道確切失去與取得的數量？目前缺少失溫、露營或衣物防護規則時，相關效果保持候選。這部作品不是價格系統或可持續聚落經濟的證據來源。

## FICTION-CANTICLE：文件價值不等於讀一次就加技能

**已查證：** Hachette 介紹災後社會對科學的恐懼，以及修會保存殘存知識；兩家出版社都以平常文件被當成重要遺物的例子介紹本書。[Hachette 書介](https://www.hachette.com.au/walter-m-miller/a-canticle-for-leibowitz)、[PRH 書介](https://www.penguinrandomhouse.com/books/114888/a-canticle-for-leibowitz-by-walter-m-miller-jr/)

**設計推論：** 同一份文件可以同時具有技術用途、歷史證據與私人意義。收藏者重視完整版本，技工重視設備型號與可讀的步驟，失主重視上面的名字；不應合成一個全世界一致的「書籍價值」。

**原創候選：** 「維修手冊」能對應一座舊泵站的型號，但缺了測試頁；它提供調查方向，不能單靠持有就完成修理。「沒有寄出的信」沒有數值能力，卻能指向應該拜訪的人。若接收者尚未建模，內容稿記錄候選對象與原因，不能臨時創造具名 NPC。

**內容審核問題：** 文件為何留在這個地方？誰能讀懂、誰在乎、讀到何處才得到哪條線索？技術解讀、任務紀錄與技能成長分開，收藏價值不暗中變成技能獎勵。

## FICTION-WOOL：探索入口也可以受資訊與制度限制

**已查證：** 作者簡介描寫艱難的生存環境、受限的外界視野，以及對談論外界的禁止；希望走出去的人面臨社會施加的後果。[Hugh Howey 官方書頁](https://hughhowey.com/books/wool/)

**設計推論：** 一道封閉入口不必只有「有防具／沒防具」兩種答案。內容可以分別記錄環境危險、守門者的理由與居民相信的說法。觀察設備、查文件或詢問不同的人，可提供不同層次的可靠資訊，而不是單靠升級揭開所有真相。

**原創候選：** 「公司門禁卡」對應某個維修入口，圖卡、舊地圖與門上標記可互相核對；聚落管理者卻認為入口已失效。玩家可以先找設備紀錄，再決定是否值得攜帶工具前往。門禁、對話、電子設備與危險區通行仍須各自實作，卡片文字本身不能授權開門。

**內容審核問題：** 傳言是否有說話者、時間、可信依據與可查證方法？神祕感應來自資訊有限，不是玩家做完動作仍看不見結算。此處沒有借用小說／影集的具體裝備祕密或結局。

## FICTION-METRO：世界是相互依存的據點與路線

**已查證：** Orion 介紹災後倖存者住在莫斯科地鐵；主角居住的車站遭遇新威脅，他必須深入地鐵傳遞警訊。[Orion 書籍介紹](https://www.orionbooks.co.uk/titles/dmitry-glukhovsky/metro-2033/9781399633703/)

**設計推論：** 地區矩陣除了列「哪裡產什麼」，還要能描述東西如何到達需求者。產地有庫存，並不等於沿線所有聚落都買得到；中斷的道路、過期情報與護送成本，都能讓同樣物資在不同位置有不同意義。

**原創候選：** 灰谷有修理工具，乾井提出維修需求，但通常運送它們的商隊尚未抵達。旅途中發現一段可繞行的小路，可以先成為情報與路線候選；不能僅憑一段事件敘事就把工具生成進乾井商店。把「供應來源」「運送路徑」「目前是否可取得」分開記錄。

**內容審核問題：** 缺貨是沒有產出、路線中斷，還是當地需求增加？事件能否指向既有世界事實？本次來源不足以證明小說的彈藥貨幣、槍械維護或防毒濾罐規則，因此不把這些遊戲改編印象當成小說研究結論。

## 可套用於內容稿的五條規則

以下是綜合上述閱讀素材後的本專案設計建議，均不是現有 runtime 欄位或已實作效果。

| 內容檢查 | 寫稿時應能回答的具體問題 | 適用既有素材名稱例子 |
| --- | --- | --- |
| 來源有因果 | 原本誰使用它？為何會留在這裡？玩家如何發現？ | 扳手、舊工作服、軍人識別牌 |
| 需求有主體 | 哪一類人因什麼實際需要想取得它？需求在什麼條件下消失？ | 種子、工具箱、醫療手冊 |
| 可用不等於必用 | 保留、交付、研究或繞路各放棄什麼？是否有一條不依賴該物品的合理路徑？ | 繩索、公司門禁卡、鳴石 |
| 未知有邊界 | 玩家現在確實觀察到什麼？還不知道什麼？本次行動確實改變什麼？ | 未標示藥劑、黑盒記憶體、沉默盒 |
| 流通有路徑 | 本地供應、外來運輸與一次性遺跡取得是否分清？改變需要哪個已存在的世界事實？ | 燃料、機械零件、罐頭 |

寫作優先順序：先確定來源與需求者，再設計事件中的取捨，最後才提議效果與數值。保留普通物品的具體用途，也保留信件、照片、奇物暫時無戰鬥收益的空間。研究來源只提供可借鑑的敘事結構，不證明這些候選會好玩；仍需後續可玩切片驗證。
