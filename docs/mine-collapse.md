# 鐵關・崩塌礦道（MIN-1～6）規格草案

狀態：**規格草案，尚未修改任何程式。** 基準為 main `330d130`（RLY-8 合併後）。風險等級：LOW（僅文件）。各片進入實作前，仍須各自的契約、測試、PR、CI 與合併；不得提前實作後續切片（Axiom 2）。本文所有數值皆為**候選值**，未經平衡驗證，須在各片契約中確定。

## 玩家想法

「我想帶機械犬去勘查礦道，把那枚控制器找回來；但要留給鐵關，還是改裝自己的犬？」

接住的既有內容：機械犬（RLY-3/4）、軍用背包（資源容量 32、道具上限 12 kg）、阿扳交情（再雇用 25 瓶蓋）。鐵關有灰谷出發的 2 天商路；重點放在深入、支撐、搬運與撤退，讓準備方式與前兩座遺跡不同。

## 設計原則

1. **基本安全資訊免費。** 玩家不必耗資源才知道「這步會不會直接死」。付費的勘查資訊必須會改變行動（例如哪條支柱能撐重貨）。
2. **主目標可一次帶回。** 合理準備的玩家能在一趟內帶回控制器；額外重貨是否值得多跑一趟由玩家決定，不強制跑腿。已打通的安全通路與捷徑，後續再訪應享受其成果。
3. **兩條控制器路都能完成主要冒險。** 犬升級帶來額外機會，不是通關門檻；留給鐵關不等於放棄後半段。
4. **同一枚控制器不能兩用。** 安裝後才形成承諾，尚未決定時可保留。
5. **後果來自真實結算。** 產水、庫存、價格變化皆走既有模擬引擎，不以敘述直接宣稱。
6. **交情來自實際共同完成的工程**，不只換雇用折扣。

## 三層勘查（MIN-2 基礎）

| 方法 | 玩家得到什麼 | 目的 |
|---|---|---|
| 現場觀察 | 看見裂縫、鬆動支柱、重物與已知退路，知道基本風險 | 沒有犬也能合理決策 |
| 普通犬勘查 | 花能源確認前方、找出可用支撐位置，或省下較慢的人工勘查 | 用能源換更好的路線判斷 |
| 控制器升級後探測 | 找到原本無法辨識的可選支道、回收位置或設備用途，實際增加一種行動 | 取得升級後出現新機會 |

現況：機械犬 1 燃料補滿至 4 能源，安全探索房內可充能且不推進日數（`simulation/relay_hound.gd`）。因此**能源本身不足以形成取捨**。MIN-2 須明定勘查、支撐、搬運各自的時間與材料成本、整備位置、支撐後永久解除的危險，並讓燃料占攜行空間、勘查耗時間、重貨影響回程，使代價共同形成選擇。不為製造緊張而取消既有充能方式。

## 容量規則

| 內容 | 沿用規則 |
|---|---|
| 廢料、燃料、水糧等既有資源 | 資源攜行容量（軍用背包 32） |
| 控制器、工具、裝備 | 正式道具重量上限（12 kg，背包自重計入） |
| 尚未取走的礦材與控制器 | 留在礦道的剩餘量與狀態 |

「喝掉水」不能替控制器騰出道具重量；畫面必須讓玩家看懂是哪邊滿了。分次搬運須保留「尚未取走的東西」，不得預設丟棄＝可再拾取的地面倉庫。控制器是否可丟棄或出售，須先決定，避免整段冒險永久無法完成。

## 鐵關現況與產水

| 項目 | 現有數值 |
|---|---:|
| 人口 | 80 |
| 每日產水 | 0 |
| 每日水需求 | 4（80 × 0.05） |
| 初始水庫存／安全目標 | 80／80 |
| 灰谷—鐵關道路 | 2 天 |
| 泉渡—鐵關補給道路 | 3 天 |

來源：`game_data/playable_world.gd`、`simulation/settlement_state.gd`。鐵關**不是已在缺水**，描述須依抵達時的真實庫存。

候選額定產水 **+2／日**（+1 不明顯、+4 跨過自給門檻影響過大），待試算。完成回饋範例：「額定日產水 0 → 2；按目前人口，每日仍需外補 2 水。」增產不會在安裝當下直接降價，效果可能表現為庫存更穩、商隊改運其他物資。水的來源需有因果交代（礦道滲流水、停擺的輸送設備，缺控制部件）。

## MIN-6 續遊起點與預算

驗收預算：**31 瓶蓋、HP 6、水糧各 1、犬能源 2、阿扳仍同行**；不把刻意再雇用後的 6 瓶蓋當成正常回城狀態。

重要細節：RLY-8 的 `shared_return` 檢查點（31 瓶蓋）保存於「確認阿扳後續約定」**之前**；約定、解雇、再雇用是其後依序執行（`tests/test_relay_journey.gd:122-132`）。若 MIN 要接「已談妥約定、阿扳仍同行」的角色，起點應為：

1. 還原真正的 `shared_return`；
2. 實際確認阿扳約定；
3. 保持同行並保存新的續遊檢查點。

水糧各 1 不足以直接帶阿扳上路：玩家先消耗補給，阿扳可能因無自己的份額離隊，而鐵關目前不能原地重新雇用他。因此 **MIN-1 前先做粗略續遊預算**，確認休養、短工與補給能合理接上遠行；MIN-6 再做完整真實驗證（動態物價、途中消耗、礦道整備、返程）。預算不得只有精確照攻略才能完成。

## 風險與升級條件

- 一般切片屬 MEDIUM：新增地點、商品／物資、產水結算（影響世界狀態）。涉及 `simulation/`，須跑全套 `tests/test_*.gd`，Exit Code 0。
- 鐵關產水是新增 `production` 變動，須確認不破壞「Living + In-Transit + Deaths == Initial Population」與離散日時序；若觸及上述公式，升級 L2。
- 阿扳、礦道居民等具名角色不得造成人口膨脹（Axiom 11）；實體 ID 用單調序號（Axiom 12）。
- 敘事層無世界狀態修改權（Axiom 3, 16）。

## 真人實玩最後要確認三件事

1. 玩家是否**主動想去**鐵關（而非被通知才去）。
2. 深入時是否**真的考慮撤退**。
3. 控制器的兩種用途是否**值得猶豫**。

不聲稱已有人類樂趣或節奏驗證；數值為候選，待各片契約與實測確定。

## 與戰鬥畫面改版的排序

目前排序：**MIN-1 → COMBAT-VIS-3A（戰場整合）→ VIS-3B/C（角色旁 HUD、指令條）→ MIN-2**。依據 2026-10-05 重新截取的實際戰鬥畫面：中央菱形戰場帶格線與厚邊，容易被誤認為戰棋棋盤；底部兩張卡與指令按鈕文字密度過高；人物視覺權重偏小。階層式指令選單（COMBAT-CMD-3）會改變操作流程，未經負責人決策不排入。MIN-1 沒有戰鬥，不受此影響；礦道開始出現戰鬥前，戰鬥畫面基礎應先穩定。

## 最先補寫的兩件事

MIN-2 的三層勘查差異、MIN-4 的「升級拿到後下一次究竟能做什麼」。這兩件事決定房間配置、控制器位置與搬運取捨。
