# PLAY-3A — 搜刮委託的實際行動

狀態：2026-09-26 本機技術驗證通過，準備與依賴的既有玩法提交一起送審。
PLAY-3 整體及玩家體驗尚未結案。

本片讓回收工單提供能實際走到的公路殘骸。玩家可以購買要求物品交件，
也可以依工單情報準備技能或工具，旅行到指定殘骸，使用現有搜刮動作，
帶著真正取得的物品返回交件。範圍包含現有搜刮工作，不增加新職業、
任務類型、物品、聲望或世界據點系統。

## 行為契約

- 接單時凍結目標地點、兩端聚落、要求物品、單程天數與來源識別。
  工單輪替不改寫已接受的委託。
- 目標是該工單的一次公路遭遇，來回方向皆可遇見；荒野繞路不經過。
  尚未接受、過期、完成及沒有目標欄位的舊工單不指定遭遇。
- 物品來自既有殘骸產出函式；工單從真實可取得的產出中選目標，
  並告知取回手法。不在結算時補塞缺少的任務物品。
- 指定來源的產出不隨日期、旅行方向或旅行日序號重擲。
  不同手法仍可取出不同東西；機械熟練、搜刮熟練與扳手需求沿用既有權限。
- 搜索、拆解及扳手處理花一天並走正常水糧消耗；順手搜刮不增加一天。
  承重不足仍留下帶不走的物品。包含略過在內的一次處理會耗用該委託地點，
  返回時不再次生成，錯過目標仍可改用購買交件。
- 經驗與練習沿用既有提交規則；委託地點不額外發 XP，也不允許重複刷取。
- 接單、遭遇及處理收據保留來源；新欄位整組缺席才視為舊合約。
  半套、型別錯誤、目標不符、來源與接受紀錄不符或已處理的活躍地點須拒絕載入。
- 投影與畫面顯示同一目標名稱；查看工單或選項不得修改世界。

## 驗收

1. 真正的購買交件流程及接單、旅行、搜刮、確認、返回、交件流程。
2. 固定灰谷第零天案例：機械背景，往乾井，三天單程；拆解取得繩索一件、
   廢料二份，額外花一天。目標為
   `salvage:job_gray_valley_salvage_0:gray_valley_dry_well:2`。
3. 失敗路徑、過期與一次處理、舊存檔、新合約及遭遇／收據損壞資料。
4. 接單、遭遇、收據及完成後保存載入；雙軌完整世界 SHA-256 相同，
   人口與全域不變量維持。
5. 全套 `tests/test_*.gd`、NPC 領域驗證器、靜態檢查與治理檢查。
6. 1280×720、1152×648 的真實工單、遭遇與結果畫面；自動化流程不代替
   玩家判斷工作差異是否有趣。

## 下一片的邊界

PLAY-3 仍要求送貨、搜刮、賞金在實際操作上有差異。此片僅處理搜刮；
送貨與賞金的下一個變更必須先有明確、可驗收的玩法契約。
既有未提交戰鬥素材／動畫屬另一批工作，不能算作本片已交付內容。
本片通過 PR／CI 並合併後，先收斂已展開的 BVIS 戰鬥呈現切片，再推進
尚未定義契約的送貨／賞金延伸。
