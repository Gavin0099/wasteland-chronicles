## Commands, ledger and atomicity

All state-changing commands use the existing allowlisted DUNGEON_ACTION. Own duel turns retain exact site/session/turn binding. Existing turn payloads retain16 fields; a shot adds5 typed fields: weapon_id, ammo_item_id, ammo_spent, ammo_remaining and firearms_rank. Validator checks known firearm/ammo/cost, finite integer bounds, damage arithmetic, skill-specific practice, terminal order and pending actual HP/ammunition. Historical full gear/inventory reconstruction and cryptographic save authenticity are not claimed.

Disposition commands bind one immutable source index: confirmed capture for handover/release/inspection, own kill/inspection for dead report, release for release report. Exact payload is {site_id,command,evidence_index}, and inspection additionally binds death_index. Own events: CUSTODY_RELEASED {site_id,room_id,capture_index}; CUSTODY_DEATH_WITNESSED {site_id,room_id,capture_index,death_index}; CUSTODY_REPORTED {site_id,city_id,evidence_index,outcome,caps_gained,standing_delta}. Actor is the living player and target is the same accepted person. Closed exact typed events validate chronological room/city, source ownership, confirmation, actual life, one disposition and ordered death proof. A pure UI inspection opens the captive window; it has no world authority. Detached stage→validate→publish keeps refusals atomic, including direct engine/API bypasses and stale confirmations.
