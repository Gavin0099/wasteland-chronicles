# QUEST-2/3 玩家流程走查基線

狀態：**真人已完成一份委託，交付後自然行為仍未完整記錄**。本紀錄依據兩個既有 Godot 流程測試、QUEST-3 實際渲染畫面、目前的任務／商店／世界狀態程式，以及玩家提供的遊戲畫面。它能確認流程和可見資訊，不能僅憑一次截圖回答「是否有趣」。沒有新增任務或修改玩法。

## 2026-09-23 首次真人操作發現

玩家接下繩索委託後抵達乾井，第 3 天、身上 46 瓶蓋，任務顯示「持有 0」且「交付物品」停用；玩家回報「接一個任務了，但是身上沒有繩索」。這是**交付前的指引缺口**，不能算作交付後會否查看世界的證據。接受委託只建立承諾，不附送物品；目前任務說明也沒有明示可在哪裡取得繩索。

程式上，乾井的繩索有 `medium` 常規供應，初始商店庫存為 3，正常買價從 30 瓶蓋起；玩家可在右側面板往下捲，展開「物品商店／區域供需」購買。交付規則只檢查玩家在乾井持有繩索，**不驗證繩索是否從灰谷運來**。因此當地購買、當地交付目前也是合法路徑，任務文字暗示的商路運送與實際 authority 不一致。待玩家繼續操作時記錄其是否找到商店、是否意識到可當地購買；先不在測試中途修 UI 或任務規則。

隨後玩家確認任務達成，提供第 7 天畫面，回報「UI 設計得不好，資訊容易被覆蓋或不容易看到」。畫面中右欄已捲至聚落及市場，任務標題與委託入口不在視野內；只剩委託內文與「已完成」。玩家水、食物皆為 0，而提示留在左下細字。這是明確的資訊呈現缺口，但畫面沒有記錄關閉結果收據後的第一個自然動作，所以仍不能據此判定 QUEST-W1 的世界回應假設。玩家關閉遊戲並授權 UI 修正後，對應改動另記於 `docs/quest-ui-readability.md`；之後的手玩須視為新 UI 版本。

## 開局到交付

兩張灰谷告示都要求把一件現有物品帶到乾井。扳手期限 8 天，獎勵 75 瓶蓋與 25 XP；繩索期限 5 天，獎勵 65 瓶蓋與 20 XP。兩者可同時接受，狀態和交付互不干擾。初始 50 瓶蓋；在未缺貨的灰谷商店，扳手 25、繩索 30，因此開局無法只用初始資金一次買齊兩件。兩個任務的目的地和行程相同，選擇主要發生在先買／先交哪件、是否留著可在路上使用的繩索，以及要帶多少水糧。路上的遭遇可要求玩家選擇，但沒有被任務本身改寫。

| 要量的事 | 目前可確認 | 手玩仍需確認 |
| --- | --- | --- |
| 為什麼接 | 告示清楚顯示物品、期限和獎勵；沒有具名委託人。XP 目前不提升技能。 | 玩家是因為乾井的需求而想幫忙，還是只把它當作賺錢按鈕？ |
| 途中有何決策 | 初始資金不足以同時買兩件；兩份任務可並行、共用同一路線。繩索交出後失去其既有道路用途。 | 資金與繩索取捨有沒有真的影響出發準備或遭遇選項？期限是否形成壓力？ |
| 完成後世界有何變化 | 物品從玩家背包移除，瓶蓋／XP 增加；完成狀態、事件紀錄與兩個世界旗標會存檔。交付物品沒有進入乾井庫存；旗標目前沒有驅動乾井價格、產出、人口、對話或畫面。 | 玩家除了結果收據與任務顯示「已完成」，能否感到乾井因自己介入而不同？ |

## 判斷

QUEST-2/3 已證明交付與多任務並存，但還沒有證明「任務 × 世界」。目前兩份委託是同一種工作；世界旗標是持久紀錄，尚不是可感知的世界後果。現有 `QuestEngine` 已共用 `DELIVER_ITEM` 的資格檢查、扣物品與結算，因此不需要為了第三份交貨單先造一套新的萬用任務框架。

## QUEST-W1 候選與啟動條件

候選問題是：**完成既有委託後，玩家能否透過世界本來的規則看見一次因果後果？** 任務只提交玩家行為；聚落的庫存、價格與其他指標由各自的世界 authority 計算。第一版只選一條可觀察後果，不同時寫入庫存、價格、人口與事件，也不由 Quest code 硬設「價格 -10%」。這是候選 slice，**真人手玩紀錄前不啟動實作**。

「交扳手 → 乾井庫存 +1 → 價格自然下降」目前不能直接當作已成立的方案。乾井的扳手供應標記為 `low`，初始商店庫存與定價目標都是 1。現行買價只在庫存**低於**目標時因短缺上升；庫存從 1 增到 2 仍是原價。賣價則只看靜態需求等級。世界尚無「水泵工棚缺扳手」的獨立需求／生產狀態。若要用這條路，先確認一個真實且玩家可觀察的短缺，再讓交付進入它；不能只加一個隱藏旗標或期待現有價格公式自行產生變化。

手玩要先觀察玩家交付後的**自然行為**，不要事先說任務可能影響世界，也不要問「乾井應不應該改變」。記錄玩家如何讀取並關閉必經的結果收據；然後記錄第一個自發動作與接下來的操作順序：查看商店、庫存、價格、聚落資訊、人口、地圖，或直接離開。只在觀察結束後問中性的「你剛才為什麼這樣做？」並記錄玩家自發說出的理由。後端旗標存在不代表玩家感受到後果。

依觀察分流：玩家主動查乾井狀態卻找不到變化，才支持啟動「任務 × 世界」的 QUEST-W1 假設；玩家只領報酬就離開，先查委託為何沒有讓他在意乾井，不急著加 simulation；世界有變化但玩家未察覺，先補 Cause Before Number／Player Knowledge。最後一種**無法靠現有兩份委託驗證**，因為它們目前沒有可見的下游世界變化。

下一次玩家手玩，從 50 瓶蓋的灰谷新角色出發：讓玩家自行比較告示、購買、處理路上遭遇並交付；觀察者不提示其查看乾井。記下收據關閉後的第一個自發動作、後續查看順序、玩家自發說出的理由與原話；在此之前，不把主觀感受標成已驗證。下一個 QUEST 玩法實驗仍取決於上述分流，不能預設為第三份交貨單或 QUEST-W1。
